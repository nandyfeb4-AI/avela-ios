# Phased implementation recommendation (proposal; not started)

This plan assumes Direction A (Tidewater) is approved. It is ordered so that
correctness lands before visual work, and each phase can ship on its own.

It slots into `docs/BUILD_PLAN.md`: Phases R1–R3 sit inside BUILD_PLAN
Phase 3 (Core UX), and R4 inside Phases 4–5. It does not change `MVP.md`
scope.

**Before you start**

- App code may have changed since this research. Another session was fixing
  correctness while it was written. Re-check file names before you begin.
- Every phase follows `docs/AGENTS.md` change discipline: tests, then a docs
  update, then a manual check.

## R0 — Decisions needed before any code

1. Approve a direction. The recommendation is A, with B's sentence-style
   Insights.
2. Decide the "To do / Done" split versus a single sorted list
   (VISUAL_DIRECTIONS open question 3).
3. Decide whether the 14-day window becomes week-aligned (open question 4).
   This changes documented semantics in DATA_MODEL, so it needs explicit
   confirmation.
4. Confirm the correctness fixes from UX_AUDIT Part 0 (trend cohort, balanced
   summary) and F9 (archive Cancel). The Insights hero design presupposes
   them.

## R2 — Today and Habit detail structure

**Components** (from COMPONENT_SPEC §2)

- `HabitRow` variants, `ProgressPips`, `UndoToast`, `DayLedger`,
  `RecoveryCard`, `StatTile`.
- `CompanionStatusCard` in its `companionDisabled` form only: a plain "2 of
  5 done" summary. This avoids shipping a placeholder companion
  (APPLE_COMPLIANCE: no placeholder screens).

**Behaviour**

- Motion and haptics table, COMPONENT_SPEC §3, including Reduce Motion
  fallbacks and the `hapticsEnabled` setting. The setting only exists if
  Settings exposes it; otherwise default to on and note that it's pending.
- AX layouts, COMPONENT_SPEC §6.

**Tests**

- Unit tests for any new pure formatting: context-line selection, ledger
  cell state from units, toast copy.
- UI tests for undo through the toast and through the row.

## R3 — Insights presentation

- `InsightsHeroCard` with its states, including the balanced-summary and
  trend-unavailable states.
- `InsightResultRow` with sentence-style copy.
- Copy is generated by pure functions over `WeeklyInsights`, and
  unit-tested for:
  - ties,
  - a single habit,
  - avoidance polarity,
  - zero eligible habits.
- Add the `#if DEBUG` populated-week fixture proposed in UX_AUDIT, so a
  real populated screenshot exists to compare against these mockups.
- Swift Charts for the weekday bar only once MVP §7's "where enough data
  exists" rule is defined. Follow the HIG charting guidance: simple, with
  accessibility labels.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Warm neutrals read as "off-white by mistake" next to system sheets | Keep sheets and forms on the system grouped background, and warm only the root screens. Review on a device in both appearances. |
| Companion card ships before the companion exists | R2 ships the disabled or plain variant only |
| Rows moving from To do to Done confuse users | Wait 0.6s before the move; usability-test it (UX_AUDIT Part 5 script, step 2) |
| Mockup icons differ from real SF Symbols | Verify every name in the SF Symbols app at the deployment target before R1 |
| Contrast regressions | Re-measure tokens after any change; dark `inkTertiary` is already flagged as below 4.5:1 |
