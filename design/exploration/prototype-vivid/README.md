# Vivid Tidewater — a colour and emphasis variant of the Balance prototype

**What this is.** A design artifact that sits beside [`../prototype/`](../prototype/).

**What stays the same.** Layout, copy, sample data and interactions are
**identical by construction**. This variant loads the Balance prototype's own
`app.js`, `data.js`, `icons.js` and `styles.css` from `../prototype/`. Its
`index.html` is generated from Balance's with only four differences: the
title, the asset paths, an extra stylesheet, and `<body class="vivid">`.

**What changes.** Colour and emphasis only, all in [`vivid.css`](vivid.css).
No production code is affected; Avela remains native SwiftUI.

## Open it

```sh
open design/exploration/prototype-vivid/compare.html   # Balance and Vivid side by side, shared setup controls
open design/exploration/prototype-vivid/index.html     # Vivid on its own, with the reviewer panel and event log
```

Both pages accept the same query parameters as the Balance prototype, for
example `compare.html?theme=dark&state=many`.

- **Static before/after board:** [`renders/board-vivid-vs-balance.png`](renders/board-vivid-vs-balance.png),
  built from [`renders/board.html`](renders/board.html).
- **12 individual stills:** `renders/{balance|vivid}-{light|dark}-{before|just|settled}.png`.
- **What the three states mean:**
  - **Before:** the initial state.
  - **Just completed:** one tap on "Drink water"; the row is settling in place
    and the undo toast is showing.
  - **Settled:** about 7 seconds later, the row has regrouped into "Done · 3"
    and the toast has expired.
- **Rendering:** every still uses Reduce Motion, so no frame is caught
  mid-animation.

## What changed, and why

Each change serves one stated purpose. Brand teal stays the hue: the Vivid
accent is within 1° of Balance (measured HSL):

| Mode | Balance | Vivid |
|---|---|---|
| Light | `#2C6B63` (172°, saturation 42%) | `#0E7468` (173°, saturation 78%) |
| Dark | `#6EBFB1` (170°, 39%) | `#3CC9B4` (171°, 57%) |

Reading surfaces (`bg`, `surface`, `surface2`) and body text (`ink`, `ink2`)
are **unchanged**. Cards stay neutral, and teal appears only on controls,
progress and feedback.

| # | Change | Purpose | Detail |
|---|---|---|---|
| 1 | Saturated brand teal | **Brand recognition** | The accent token for light and dark. It is what you'd recognise from across the room and in widgets; it carries into the app icon direction (ICON_SYSTEM §3). |
| 2 | Teal outline on empty completion rings | **Action discovery** | Was grey ink at 80% opacity (3.6:1 light, 3.2:1 dark). Now full accent (5.7 / 8.1). The control reads as "tap me", not as a decoration. |
| 3 | Filled teal Add button | **Action discovery** | It stands out as the screen's only creation action. Native analogue: a toolbar button with `.buttonStyle(.glassProminent)` tinted with `AccentColor`, a system style rather than a custom one. |
| 4 | Teal Habits pillar value ("2 of 5") | **Progress emphasis** | The one summary number is in brand colour. The pips stay as before. |
| 5 | Outlined unfilled weekly pips | **Progress emphasis + contrast fix** | Unfilled segments were `surface2` fills, measured at 1.2:1 and 1.1:1 against the card, so "2 of 3" depended on the text. They are now outlined (6.0 / 5.7). |
| 6 | Teal wash on a settling row | **Feedback** | While a just-completed row waits to regroup, it gets a quiet tint (`doneWash`). This confirms *which* row changed, and stops under Reduce Motion (no transition). |
| 7 | Branded toast with a solid Undo button | **Feedback + action discovery** | The toast uses deep teal in light mode and pale teal in dark mode. Undo becomes a solid, inverted pill (11.5 / 14.2) instead of a translucent grey one, so the recovery path is the most visible thing in the toast. |
| 8 | Tinted selected tab | **Brand recognition** | Uses `accentSoft` instead of neutral `surface2`. The label stays at or above 4.5:1 (it initially measured 4.49 and the tint was lightened to fix it). |
| 9 | Tertiary ink, light `#636C67` → `#5C6560`, dark `#78837E` → `#8E9994` | **Contrast fix** | Closes the known dark-mode gap: 4.3:1 → 5.7:1 on cards. Light mode moves from 5.4 to 6.0. |
| 10 | Full-opacity "missed" ring; outlined "skipped" and "no check-in" ledger cells | **Contrast fix** | The missed ring was 2.9 / 2.8:1 because of 70% opacity, below the 3:1 non-text target. It is now 6.0 / 5.7. Ledger states still differ by shape as well as colour. |

## What this does *not* claim

- **No colour change here is evidence of better adherence, retention or
  habit success.** None of these changes has been tested with users, and no
  claim in this folder should be read that way.
- The purposes above (brand recognition, action discovery, feedback) are
  **design intentions**, not measured outcomes. "Action discovery" means the
  control is more visually distinct; whether people actually find it faster is
  an open question (see below).
- A browser can't validate how these colours render through native Liquid
  Glass, on OLED displays, with Increase Contrast or Smart Invert, or under
  True Tone. The Balance prototype's limits all apply here too: no native
  VoiceOver, Dynamic Type, haptics or SwiftUI rendering.

## Risks to watch

These are visible in `compare.html?state=many`:

- **Every empty ring is now teal.** With 11 habits that is 8 teal rings at
  once. That helps discovery, but it may read as busier or more demanding. It
  also flattens the hierarchy between the Add button and the completion
  controls. Mitigation if tests show it: keep the ring teal only for the
  first to-do row, or use a thinner ring.
- **"Calm, not punitive"** (VISION). Vivid stays clear of red and alarm
  colours, but more saturation is still more insistent. Check that it doesn't
  read as pressure.
- **The settling wash in dark mode is subtle** (`#13302C` on `#191F1D`). It
  is feedback *in addition to* the filled check and the toast, never the only
  signal.

## How to compare with users

Extend `../prototype/USABILITY_SCRIPT.md`. Don't run a separate study.

- **Between participants:** randomise which variant each participant uses.
  Don't show both to the same person first, or preference comparisons will
  dominate.
- **Measure behaviour, not liking:**
  - first-tap accuracy on task 1;
  - whether they notice which row changed (task 2);
  - how long they take to find Undo (tasks 3 and 4).
- **Ask about tone afterwards:** "Did the colours feel calm, energetic, or
  pushy?"
- **What to conclude:** only whether Vivid changes discovery or tone. Five or
  six participants cannot tell you anything about adherence.

## How it was checked

- **Interactions:** the same 27-check scripted suite used for the Balance
  prototype passed **27 / 27 against Vivid** in headless Chrome, using
  throwaway copies outside the repo. The checks cover:
  - deferred regroup and the repeat-tap guard;
  - focus moves and toast Undo;
  - recovery and weekly copy;
  - detail navigation and the back-focus restore;
  - the immediate, many and empty modes.
- **Visual:** the 12 stills and the board, plus `compare.html` rendered in
  dark mode with the many-habit state.
- **Markup:** `diff ../prototype/index.html index.html` shows only the four
  intended differences.

## Native mapping (if adopted)

| Prototype | SwiftUI |
|---|---|
| Accent tokens | The `AccentColor` asset with light, dark and Increase Contrast variants |
| Other new tokens (`doneWash`, `track`, toast colours) | Named colour assets |
| Add button | `.buttonStyle(.glassProminent)` |
| Ring outline | `.stroke(Color.accentColor)` |
| Settling wash | `.background` driven by the existing settling state, with `.animation(nil)` under `accessibilityReduceMotion` |

Re-measure all contrast values on a device afterwards.
